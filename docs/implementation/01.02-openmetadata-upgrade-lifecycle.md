# IMP-01.02 — Make OpenMetadata apply safe to repeat under study quotas

Status: proposed; not implemented by this review.
Priority: P1 — before closing 03.10.
Dependencies: None.

## Evidence and impact

`Makefile: apply-openmetadata` waits for the new adapter before upgrading the server to its reduced resource budget. Earlier quota failures required manually stopping the old server. The adapter mounts its ConfigMap with subPath and has no content-triggered rollout; changing that file alone does not prove running NGINX has reloaded it.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`Makefile` (OpenMetadata recipes only); `clusters/dev/openmetadata/**`; `platform/charts/openmetadata/**`; `tests/integration/openmetadata/test_apply_lifecycle.py`; `docs/runbooks/openmetadata.md`.

## Bounded implementation steps

Render the pinned chart and measure the effective pod budget including init containers and rollout surge. Implement a repeatable upgrade sequence that fits the quota, using a supported Recreate strategy or a narrowly scoped lifecycle helper if needed. Document the brief local outage. Check the target context before mutation. Make adapter configuration changes trigger a rollout. Keep bootstrap prerequisites distinct from component-only upgrades. Add useful failure diagnostics without printing secret values.

## Acceptance and verification

Test command order and early failure with fake kubectl/Helm commands. A failed preflight must not scale anything down. Document recovery if apply fails after shutdown. In an authorized live check, apply twice, then change a harmless adapter setting and verify a new pod loads it. Record desired/available replicas and effective quota consumption.

## Non-goals and stop conditions

Do not raise shared quotas automatically, restart unrelated services, or delete a cluster/PVC. Do not launch a second expensive cluster to prove fresh install on the laptop.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
