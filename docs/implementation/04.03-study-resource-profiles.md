# IMP-04.03 — Turn laptop limits into an executable preflight

Status: proposed; not implemented by this review.
Priority: P2 — before adding another heavy stack.
Dependencies: None.

## Evidence and impact

The charter specifies 16 GiB RAM and cluster requirements reserve up to 8 GiB for workloads. The blueprint recommends profiles, but deployment dependencies keep reapplying many platform services. Namespace limits alone do not measure laptop memory use or rollout overlap.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

New `config/study-profiles.yaml`; new `scripts/cluster/check-study-profile.py`; new `tests/unit/cluster/test_study_profiles.py`; `docs/platform/cluster-requirements.md`; new `docs/runbooks/study-profiles.md`.

## Bounded implementation steps

Inventory Python-only, Compose, foundation, data-catalog and future accelerator profiles. Record dependencies, port reservations, estimated requests/limits and measured usage when available. Implement a read-only preflight that reports host headroom, disk and effective pod/rollout budgets, with clear unknown measurements. Document pause/resume and persistent volumes for each profile.

## Acceptance and verification

Test budget calculation with fixtures, including init containers and overlapping rollout pods. Run the script read-only on the laptop when available and record measured versus estimated values. A failing preflight must not stop workloads or change quotas.

## Non-goals and stop conditions

Do not implement automatic cleanup, erase PVs, or claim all phases fit concurrently. Hardware availability remains a separate prerequisite.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
