# IMP-02.01 — Invalidate ingestion reuse when processing changes

Status: proposed; not implemented by this review.
Priority: P1 — correctness before reusing datasets.
Dependencies: None.

## Evidence and impact

`matching_curated_dataset()` compares only input checksums. Identical CSVs can bypass a changed transform or quality suite. It reads metadata from main and only afterward resolves the head, allowing a concurrent update to produce mismatched metadata and commit identity.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`src/ml_platform/ingestion/baseline.py`; `src/ml_platform/ingestion/lakefs_client.py`; `src/ml_platform/data/transforms.py`; `tests/integration/ingestion/**`.

## Bounded implementation steps

Define a processing fingerprint from input bytes, transformation implementation/configuration, dataset schema, quality suite and relevant dependency identity. Persist it in dataset metadata. Resolve main to one immutable commit first and read/cache-match all metadata through that ref. Treat old metadata without the fingerprint as a cache miss. Preserve the old snapshot.

## Acceptance and verification

Extend the fake lakeFS tests: unchanged inputs and processing give a no-op; changed transform, suite or schema force a new result; a concurrent head change cannot mix revisions. Verify the old commit still serves its old bytes. Run `.venv/bin/python -m pytest tests/integration/ingestion tests/unit/data`.

## Non-goals and stop conditions

Do not hash the entire dirty repository as a substitute for explicit inputs, or force cache misses merely because documentation changed.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
