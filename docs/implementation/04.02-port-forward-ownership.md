# IMP-04.02 — Detect occupied ports and failed forwards

Status: proposed; not implemented by this review.
Priority: P2 — repeated local-debugging issue.
Dependencies: None.

## Evidence and impact

Several port-forward helpers declare readiness when any listener accepts the local port, without checking whether their child process exited. Phase 0 Grafana and Forgejo both document port 13000. Multiple services/profiles can therefore cause misleading connectivity results.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`clusters/dev/openmetadata/register_openmetadata_oidc.py`; `clusters/dev/openmetadata/register_baseline_metadata.py`; `tests/integration/openmetadata/**`; `docs/runbooks/openmetadata.md`; new `docs/implementation/local-port-map.md`.

## Bounded implementation steps

Fix the OpenMetadata helpers first: check for an occupied port, watch child exit status, capture bounded diagnostics, and confirm the intended service identity before use. Do not silently reuse an unknown listener. Clean up only processes started by the helper. Write a table of existing local ports and profile collisions, including Grafana/Forgejo, without changing unrelated defaults.

## Acceptance and verification

Use a temporary unrelated listener and a fake kubectl process that exits early; both must fail promptly. Verify normal cleanup and exception cleanup leave no child process. Never kill the listener used by the conflict test until that test's own cleanup.

## Non-goals and stop conditions

Do not consolidate every helper in the repository or use killall/pkill to free ports. Broader reuse can follow a proven helper.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
