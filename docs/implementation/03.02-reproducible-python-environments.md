# IMP-03.02 — Make clean-checkout environments explicit

Status: proposed; not implemented by this review.
Priority: P2 — developer reproducibility.
Dependencies: None.

## Evidence and impact

`pyproject.toml` exposes test/data/data-quality extras but baseline training and serving import MLflow, sklearn, FastAPI and related libraries outside those extras. Version declarations are spread between Makefile, requirements, images and config/versions.yaml. Ingestion locates examples/contracts via repository-relative paths.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`pyproject.toml`; `config/versions.yaml`; `config/requirements/**` (new); `examples/sklearn_baseline/README.md`; `docs/version-policy.md`; new `tests/config/test_environment_contract.py`.

## Bounded implementation steps

Document and lock separate minimal test, data, and baseline-ML environments for the supported Python version. Preserve the minimal core package with no unnecessary ML imports. State which commands require a source checkout versus an installed package. Select one authoritative version source and add consistency checks for duplicated active declarations; do not mass-upgrade dependencies.

## Acceptance and verification

In a temporary venv with approved package access, install the declared extras/lock and smoke-import each promised command dependency. Record exact install/test commands and any network blocker. Check version consistency offline. Never use the existing developer venv as the sole proof of reproducibility.

## Non-goals and stop conditions

Do not add every future LLM library or require all profiles to share one giant environment.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
