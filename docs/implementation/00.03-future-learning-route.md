## A second dataset is an architectural test

After the housing path works, choose one small second dataset with a different feature schema and reuse the same orchestration and evidence contracts. Keep dataset-specific mapping inside adapters. Verify that adding it does not require copying the platform's HTTP, lineage, registry or failure-reporting logic.

Do not require a generic feature-engineering DSL. A second concrete implementation is enough to reveal the correct reusable boundary.

## Learning artifacts to keep small

For each major capability, retain one runnable example, one deliberate failure case, a concise explanation of state/ownership, and a dated result with resource measurements. Compare another tool only when answering a specific question, such as runtime memory use or retriever recall.

Suggested independent manual exercises:

- Trace a model version back to exact input bytes and the quality result that allowed them.
- Change a quality rule while keeping the CSV identical and explain why cache reuse should change.
- Stop a downstream service and identify whether the operation committed, failed before commit, or needs reconciliation.
- Explain which credentials a training job actually needs versus the administrator running bootstrap.
- Restore one isolated piece of state and state precisely what remains unrecoverable.

These exercises connect the infrastructure to ML engineering decisions. They are more valuable than treating every service installation as an equal unit of platform completeness.
