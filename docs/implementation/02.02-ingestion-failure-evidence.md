# IMP-02.02 — Preserve failure events and distinguish post-commit failures

Status: proposed; not implemented by this review.
Priority: P1 — operational correctness.
Dependencies: None.

## Evidence and impact

`scripts/data/ingest_baseline.py` writes collected events only after ingestion succeeds, so an emitted FAIL is lost on exceptions. Source hashing occurs before the ingestion try block. `create_branch_from_source()` catches every exception and may try bootstrap writes after an unrelated API failure. Merge precedes manifest publication.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`scripts/data/ingest_baseline.py`; `src/ml_platform/ingestion/baseline.py`; `src/ml_platform/ingestion/lakefs_client.py`; `tests/integration/ingestion/**`; `tests/integration/lineage/**`.

## Bounded implementation steps

Persist collected events in a finally path while preserving the original failure exit status. Narrow branch bootstrap fallback to the verified empty-repository error only. Add explicit failure stages, including before input checksums exist and after a commit/merge succeeded. Report the committed revision when evidence publication fails, so a retry can reconcile rather than claim no data was written. Write local evidence atomically.

## Acceptance and verification

Inject missing input, 401/403, timeout, branch conflict, quality failure and manifest-write failure. Verify bootstrap is not attempted after auth/transport errors; FAIL survives CLI termination without secrets; a post-commit failure records the revision. Run `.venv/bin/python -m pytest tests/integration/ingestion tests/integration/lineage`.

## Non-goals and stop conditions

Do not silently roll back published data, suppress the original exception, or change the current bad-input test to require a successful run manifest.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
