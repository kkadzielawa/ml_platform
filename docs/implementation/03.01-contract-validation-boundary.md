# IMP-03.01 — Use one tested contract-validation implementation

Status: proposed; not implemented by this review.
Priority: P2 — before extending schemas.
Dependencies: None; coordinate schema changes with IMP-02.03.

## Evidence and impact

The run-manifest validator is duplicated in tests. Dataset tests have another validator with different keyword support. A direct check of the runtime validator with minimum=1 and value=0 returned no errors; current run-schema usage does not by itself prove an existing payload violation, but future schema extensions can silently go unenforced.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`src/ml_platform/run_manifest/**`; `tests/contracts/**`; `pyproject.toml`; `config/versions.yaml`; `docs/conventions.md`.

## Bounded implementation steps

Replace duplicated runtime/test schema interpretation with a pinned standards-compliant validator supporting the declared schema draft. Keep the existing public validate_manifest entry point and useful field paths. Validate schemas themselves, resolve only approved local references, and configure format checks explicitly where required. Tests should call production validation. If adding a dependency conflicts with the local stdlib constraint, record that decision rather than silently implementing a partial standard.

## Acceptance and verification

Verify all existing positive/negative fixtures plus numeric bounds, const, extra fields and invalid schemas. Prove unsupported remote reference resolution cannot cause unexpected network access. Run `.venv/bin/python -m pytest tests/contracts tests/integration/ingestion`.

## Non-goals and stop conditions

Structural validation does not prove that a URI exists, metrics are true, or permissions are correct; keep those as separate runtime checks.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
