# IMP-05.04 — Inventory recovery gaps and prove one database restore

Status: proposed; not implemented by this review.
Priority: P2 — before relying on persistent catalog state.
Dependencies: None.

## Evidence and impact

Phase 1 backup deliberately excludes secrets and volume data. The restore drill copies a fixture row/object and honestly documents that it is not database PITR or native Garage recovery. New Keycloak/lakeFS/OpenMetadata state increases the gap between reinstalling manifests and recovering data.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`docs/runbooks/backup.md`; `docs/runbooks/restore.md`; new `scripts/backup/openmetadata-dump.sh`; new `tests/dr/openmetadata/**`.

## Bounded implementation steps

First inventory per-service metadata, objects, keys and rebuildable indexes, with current protection and recovery dependencies. Add a scoped OpenMetadata logical export and restore to a separate disposable database, using pinned compatible tooling. Store a test copy outside the source database failure domain. Record what happens to identity, artifacts and indexes; explicitly exclude these from the one-database proof where not tested.

## Acceptance and verification

With authorization for the target resources, restore a known catalog fixture into the separate target and compare entity identities and counts. Verify the source is untouched and document missing dependencies. Record elapsed time as a measurement, not an SLA. Do not advertise full-platform recovery.

## Non-goals and stop conditions

Do not delete source volumes, assume Garage-hosted backups survive loss of Garage itself, or expand this into multi-node HA. Phase 12.15 still owns broader disaster recovery.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
