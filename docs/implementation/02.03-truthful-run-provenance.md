# IMP-02.03 — Separate real artifacts from placeholder provenance

Status: proposed; not implemented by this review.
Priority: P1 — reproducibility.
Dependencies: None.

## Evidence and impact

`local_python_image_refs()` hashes sys.version and labels the result an image digest, with SBOM/signature paths it does not generate. Ingestion labels a version-catalog hash as a dependency-lockfile hash. Baseline training records model bytes in image fields and uses placeholder signature/SBOM paths.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`contracts/run-manifest.schema.json`; `contracts/examples/run-manifests/**`; `src/ml_platform/run_manifest/**`; `src/ml_platform/ingestion/baseline.py`; `examples/sklearn_baseline/train.py`; corresponding contract, ingestion and training tests; `docs/conventions.md`.

## Bounded implementation steps

First define a backward-compatible local-execution representation: an actual Python environment fingerprint is not an OCI image digest. Allow explicitly absent image/signing evidence for local execution, with a reason. Keep strict image provenance for container runs. Store model checksum separately from image identity. Only populate lockfile hashes and artifact URIs when they refer to existing, verifiable objects. Update the contract version and fixtures explicitly.

## Acceptance and verification

Test local and container manifests, absent optional evidence, missing required container digest, and artifact checksum verification. Ensure old supported fixtures remain readable or document a migration. Validate runtime output against the shared contract implementation.

## Non-goals and stop conditions

Do not create dummy files or fabricate digests to satisfy required fields. Do not build a new signing pipeline; reuse existing signed-image work when available.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
