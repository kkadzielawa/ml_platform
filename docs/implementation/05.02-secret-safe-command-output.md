# IMP-05.02 — Keep bootstrap credentials out of command transcripts

Status: proposed; not implemented by this review.
Priority: P1 — before recording more deployment evidence.
Dependencies: None.

## Evidence and impact

OpenMetadata Makefile registration recipes print assignments containing the actual environment-supplied passwords and client secret. Applying create-secret --dry-run piped to apply can also retain secret material in client-side last-applied annotations. Existing redaction relies partly on enumerated known values.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`Makefile` (OpenMetadata recipes); `clusters/dev/openmetadata/register_openmetadata_oidc.py`; `clusters/dev/openmetadata/register_baseline_metadata.py`; `tests/integration/openmetadata/**`; `docs/runbooks/openmetadata.md`.

## Bounded implementation steps

Use already exported environment variables without repeating secret values in echoed recipes or argv. Add a test harness that sets unique synthetic canary credentials and captures normal and failed command output. Choose a documented secret reconciliation approach that avoids storing payloads in last-applied annotations for newly managed secrets; treat any cleanup of existing annotations as a separate precise migration.

## Acceptance and verification

Assert stdout, stderr, diagnostic reports and command traces never contain canary credentials or bearer tokens. Preserve explicit failure messages and make variable overrides. Run tests entirely with fake commands; do not print or scan actual cluster secret values.

## Non-goals and stop conditions

Do not rotate unrelated credentials or claim generic secret scanning proves all possible disclosures absent.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
