# IMP-01.03 — Verify the complete OpenMetadata login session

Status: proposed; not implemented by this review.
Priority: P1 — before closing 03.10.
Dependencies: IMP-01.01 and IMP-01.02.

## Evidence and impact

`tests/integration/openmetadata/test_openmetadata.py` checks the first redirect and adapter discovery/JWKS, then uses a password-grant token for catalog lookup. It never completes the browser authorization-code callback. Thus a passing redirect would not prove the login session works.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`tests/integration/openmetadata/**`; `clusters/dev/openmetadata/oidc-discovery-adapter.yaml`; `clusters/dev/openmetadata/register_openmetadata_oidc.py`; `platform/charts/openmetadata/values-dev-kind.yaml`; `docs/runbooks/openmetadata.md`.

## Bounded implementation steps

Preserve the current study route while testing it end to end. Start owned localhost forwards, follow the login page, authenticate the designated study user, complete any consent step and callback, then fetch an authenticated resource with the resulting session. Verify issuer consistency through code exchange and logout. Use the pinned server's actual session API, not a guessed endpoint. Disable or redact proxy access logging for authorization codes, tokens and user identifiers. Clarify the two fixed local ports and reject unsupported overrides before apply.

## Acceptance and verification

Include successful login, wrong credentials, invalid state, expired or replayed callback where supported, and logout. No captured cookies, codes or passwords in reports. Use an opt-in live test and a documented manual browser checklist; record the exact observed outcome. Password-grant success alone cannot close this task.

## Non-goals and stop conditions

Do not disable state/nonce/signature checks, change the global Keycloak hostname, or substitute a fake successful callback. A shared ingress redesign needs a separate reviewed decision.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
