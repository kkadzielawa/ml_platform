# IMP-01.04 — Register actual quality results in OpenMetadata

Status: proposed; not implemented by this review.
Priority: P1 — missing 03.10 deliverable.
Dependencies: None; coordinate with IMP-02.04 selected route.

## Evidence and impact

`register_seed()` creates team, service, database, schema, table and ownership only. `catalog-seed-configmap.yaml` contains a static quality result of pass; the static test merely asserts that value. The runbook says quality is cataloged, which the registration code does not establish.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`clusters/dev/openmetadata/register_baseline_metadata.py`; `clusters/dev/openmetadata/catalog-seed-configmap.yaml`; `tests/integration/openmetadata/**`; `docs/runbooks/openmetadata.md`.

## Bounded implementation steps

Add an explicit quality-report input. Map a real report to the pinned OpenMetadata quality entity/result API, including dataset revision, observed timestamp, suite identity and originating run. Keep the small seed as an explicitly labeled demonstration fixture when no measured report exists. Do not manufacture a pass from missing input. Separate entity upsert from result publication so retries reuse the same result identity.

## Acceptance and verification

Mock API tests must assert report-derived pass and fail values, missing/malformed-report rejection, and idempotent retry. The opt-in live test must retrieve the stored quality result from OpenMetadata, not inspect the seed file. Run `.venv/bin/python -m pytest tests/integration/openmetadata`.

## Non-goals and stop conditions

Do not deploy Airflow or broad ingestion connectors. Do not describe a demonstration result as a measured pipeline run.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
