# IMP-01.01 — Make persisted OpenMetadata OIDC updates verifiable

Status: proposed; not implemented by this review.
Priority: P1 — before closing 03.10.
Dependencies: None.

## Evidence and impact

`clusters/dev/openmetadata/sync_oidc_configuration.py` updates a nested JSON path and interprets an update count of one as success. A missing configuration row returns zero and is reported as already synchronized. If a parent JSON object is absent, a nested update can leave the requested value unset. The last corrected invocation in the conversation was aborted; success is not established.

Read [the review README](README.md) first. Recheck these observations against the working tree before implementation.

## Proposed allowed paths

`clusters/dev/openmetadata/sync_oidc_configuration.py`; new `tests/integration/openmetadata/test_oidc_sync.py`; `docs/runbooks/openmetadata.md`.

## Bounded implementation steps

Read the synchronizer, Helm authentication values, and issue 03.10. Add a read-only preflight that checks the pinned schema/version and exactly one settings row. Prefer a supported configuration API only if verified for the pinned server; otherwise retain a narrowly scoped, documented SQL migration. Preserve all other settings and secrets. Verify both stored values after the update; never equate zero changed rows with success without reading them. Handle an absent parent deliberately or fail before mutation. Bound subprocess duration. Restart only if settings changed, and verify the replacement pod is ready.

## Acceptance and verification

Use mocked command responses for already-correct settings, missing row, missing parent, update failure, read-back mismatch, and successful change. Assert no restart after failure or no-op and no secrets in output. Run `.venv/bin/python -m pytest tests/integration/openmetadata/test_oidc_sync.py`. Live migration is a separate, explicitly reported check after IMP-01.02.

## Non-goals and stop conditions

Do not reset the database, recreate credentials, delete volumes, or replace the shared Keycloak realm.

If a required API, fixture, version or permission is unavailable, report the exact blocker. Do not fabricate a successful result. Hand off changed files, verification mode/outcomes and remaining risks; commit/push only when requested.
